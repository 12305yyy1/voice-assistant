## 4. 原项目接口

### 4.1 OTA HTTP 接口

**请求**

```http
POST /xiaozhi/ota/ HTTP/1.1
Host: 192.168.0.110:8003
device-id: aa:bb:cc:dd:ee:ff
client-id: stage2-test
Content-Type: application/json
```

请求体（可省略，但建议带 `application.version`）：

```json
{
  "application": { "version": "1.0.0" },
  "board": { "type": "stage2-test" }
}
```

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `device-id` | Header | 是 | 设备 ID，建议 MAC 格式 |
| `client-id` | Header | 是 | 客户端 ID |
| `device-model` | Header | 否 | 设备型号；也可用 body `board.type` |
| `device-version` | Header | 否 | 当前固件版本；也可用 body `application.version` |
| `application.version` | Body | 否 | 设备当前版本，默认 `0.0.0` |
| `board.type` | Body | 否 | 设备型号，默认 `default` |

**实际响应（200）**

```json
{
  "server_time": {
    "timestamp": 1793512927879,
    "timezone_offset": 480
  },
  "firmware": {
    "version": "1.0.0",
    "url": ""
  },
  "websocket": {
    "url": "ws://192.168.0.110:8000/xiaozhi/v1/",
    "token": ""
  }
}
```

- 未配置 MQTT 网关时返回 `websocket`；`firmware.url` 为空表示 `data/bin` 下没有新固件。
- 缺少 `device-id` 或 `client-id` 会返回错误（当前实现为 500 并记录日志）。

### 4.2 WebSocket 接口

**连接地址**

```text
ws://192.168.0.110:8000/xiaozhi/v1/?device-id=stage2-test&client-id=stage2-test
```

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `device-id` | Query 或 Header | 是 | 设备 ID；缺失时连接会被关闭 |
| `client-id` | Query 或 Header | 否 | 客户端 ID |
| `authorization` | Query 或 Header | 否 | 开启 `server.auth.enabled` 后使用 |

**客户端 hello 消息**

```json
{
  "type": "hello",
  "version": 1,
  "transport": "websocket",
  "audio_params": {
    "format": "opus",
    "sample_rate": 24000,
    "channels": 1,
    "frame_duration": 60
  },
  "features": {}
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `type` | 是 | 固定 `hello` |
| `version` | 是 | 协议版本，当前 `1` |
| `transport` | 是 | `websocket` |
| `audio_params.format` | 是 | `opus` |
| `audio_params.sample_rate` | 是 | `24000`（也支持 8000/12000/16000/48000） |
| `audio_params.channels` | 是 | `1` |
| `audio_params.frame_duration` | 是 | `60`（毫秒） |
| `features` | 否 | 客户端能力，如 `mcp`、`aec` |

**服务端 welcome（实际抓取）**

```json
{
  "type": "hello",
  "version": 1,
  "transport": "websocket",
  "audio_params": {
    "format": "opus",
    "sample_rate": 24000,
    "channels": 1,
    "frame_duration": 60
  },
  "session_id": "<由服务端生成>"
}
```

**音频与后续消息**

- 音频为二进制 Opus 帧，采样率 24 kHz、单声道、60 ms/帧。
- 语音对话后续还有 `listen`、`tts`、`stt` 等 JSON 消息；完整设备协议请参考上游仓库及小智通信协议文档。
- 本次已验证：握手成功并收到 `welcome`；LLM 已配置 DeepSeek，并用下面的“文本模拟输入”验证了 LLM + TTS 音频输出。

**文本模拟输入（无麦克风/无 ESP32 联调）**

原项目支持在 `listen` 消息里直接携带 `text`，服务端会跳过 ASR，把文本交给 LLM：

```json
{
  "type": "listen",
  "state": "detect",
  "mode": "manual",
  "text": "请用一句话介绍你自己。"
}
```

服务端随后会返回：

```text
stt  -> 用户文本回显
tts  -> start / sentence_start（逐句） / stop
binary -> Opus 音频帧（24 kHz、60 ms/帧）
```

`stage2\verify_dialogue.py` 就是按这个方式验证的，详见 6.3 节。实际麦克风音频的 ASR 由 8010 的 `/asr` 单独验证。

### 5.2 语音识别 `POST /asr`

`multipart/form-data`：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | File | 是 | 音频文件，支持 WAV/MP3/OGG/M4A；建议 16 kHz、单声道、16-bit；建议小于 10 MB |

示例：

```powershell
curl.exe -X POST `
  -F "file=@F:\PBL\voice-assistant\backend\stage2\samples\asr_sample.wav" `
  http://127.0.0.1:8010/asr
```

成功响应（200）：

```json
{
  "text": "你好，我是小雨，一个会听会说，也会陪你聊天的智能语音助手，很高兴认识你。",
  "engine": "SherpaASR",
  "elapsed_ms": 547
}
```

> 这是实际识别结果。原音频说的是“我是小语”，模型识别成了“小雨”，属于小模型正常误差，不影响接口验证。

错误码：

| HTTP | 场景 |
| --- | --- |
| 400 | 文件为空、音频无法解析、短于 200ms |
| 422 | 音频有效但未识别到文字（静音/噪声） |
| 500 | ASR Provider 内部异常 |

### 5.3 语音合成 `POST /tts`

`application/json`：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `text` | string | 是 | 待合成文本，1–500 字符 |
| `voice` | string | 否 | EdgeTTS 音色，默认 `zh-CN-XiaoxiaoNeural`；例如 `zh-CN-YunxiNeural` |

示例：

```powershell
curl.exe -X POST http://127.0.0.1:8010/tts `
  -H "Content-Type: application/json" `
  -d "{\"text\":\"今天天气不错，适合出门散步。\"}" `
  -o F:\PBL\voice-assistant\backend\stage2\outputs\tts.mp3
```

成功响应：

- `200 OK`
- `Content-Type: audio/mpeg`
- 响应头 `X-TTS-Elapsed-Ms`：合成耗时
- Body：MP3 二进制

实际验证产物：`stage2\outputs\roundtrip_tts.mp3`，20,160 bytes，时长 3.36 s，格式 MP3。

错误码：

| HTTP | 场景 |
| --- | --- |
| 400 | `text` 为空 |
| 502 | EdgeTTS 网络/音色错误，或未生成有效音频 |

### 5.4 大模型对话 `POST /chat`

`application/json`：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `text` | string | 是 | 本轮用户文本，1–2000 字符 |
| `history` | array | 否 | 历史消息，元素为 `{"role":"user"/"assistant","content":"..."}`；最多使用最后 10 条 |

示例：

```powershell
curl.exe -X POST http://127.0.0.1:8010/chat `
  -H "Content-Type: application/json" `
  -d "{\"text\":\"请用一句话介绍你自己。\"}"
```

成功响应（200）：

```json
{
  "reply": "我是小智，一个简洁友好的中文语音助手，很高兴为你服务。",
  "model": "deepseek-flash",
  "elapsed_ms": 2704
}
```

错误码：

| HTTP | 场景 |
| --- | --- |
| 400 | `text` 为空 |
| 502 | DeepSeek 网络/鉴权/模型错误，或空回复 |

> 实际记录：`stage2\outputs\chat_test.json`。

### 5.5 代码示例（Python）

```python
import requests

# ASR
with open(r"stage2\samples\asr_sample.wav", "rb") as f:
    r = requests.post("http://127.0.0.1:8010/asr",
                      files={"file": ("asr_sample.wav", f, "audio/wav")},
                      timeout=60)
print(r.json())

# LLM
r = requests.post("http://127.0.0.1:8010/chat",
                  json={"text": "请用一句话介绍你自己。", "history": []},
                  timeout=60)
print(r.json())

# TTS
r = requests.post("http://127.0.0.1:8010/tts",
                  json={"text": "今天天气不错，适合出门散步。"},
                  timeout=60)
open("tts.mp3", "wb").write(r.content)
```

- `torch==2.2.2`、`torchaudio==2.2.2`

- `silero_vad`、`transformers`（VAD 使用 onnxruntime，ASR 使用 sherpa-onnx，均不需要）

因此默认的 `ASR: FunASR` **不可用**；当前选择的是项目支持的 `SherpaASR`。如果必须改用 FunASR：

```powershell
# 会下载 PyTorch 约 200 MB、FunASR 依赖及 SenseVoiceSmall 模型
..\.venv\Scripts\python.exe -m pip install -r .\main\xiaozhi-server\requirements.txt
# 下载 SenseVoiceSmall 到 main\xiaozhi-server\models\SenseVoiceSmall\model.pt
# 然后把 selected_module.ASR 改为 FunASR 并重启
```

## 9. 已知限制与风险

1. **WS 设备级音频未联调**：阶段一 UI 已通过 HTTP 完成“音频 → ASR → DeepSeek → TTS”全链路；8000 WebSocket 只验证了握手、`listen.detect` 文本输入和 TTS 音频输出，尚未把 Opus 音频流直接灌入设备协议。
2. **A3 未部署**：任务允许本地部署，但本次没有 A3 主机地址/SSH 凭据；如需迁移，请提供访问方式。
3. **SherpaASR 精度**：小模型会出现同音字（“小语”→“小雨”），生产场景建议换 FunASR、讯飞或云端 ASR。
4. **无鉴权/无 TLS**：8010 接口和 8000 WebSocket 都是明文，且 8010 没有鉴权；只适合本机/局域网调试，**不要直接暴露到公网**。
5. **端口/防火墙**：其他设备访问 192.168.0.110 需要放行 8000/8003/8010；公网部署还需 Nginx/HTTPS/WSS。
6. **进程管理**：当前由 `stage2/run_services.py` 启动，不是 Windows 服务；重启机器后需要重新执行 `run_services.py`。
7. **全量依赖未装**：没有 PyTorch/FunASR；如果课程验收要求 `pip install -r requirements.txt` 全量安装，需要补装并切换默认 ASR。
8. **模型许可**：SenseVoice 模型来自 ModelScope，EdgeTTS 使用微软在线服务；商用前请自行确认模型与服务条款。
9. **LLM Key/费用**：DeepSeek Key 保存在本机 `data\.config.yaml`，调用会产生费用；不要提交到公开仓库或发到公开群。若 Key 泄露，请立即在 DeepSeek 控制台吊销并更换。
